# GLIBC & KMOD シンボルバージョン適応ツール (CAdapt)

このプロジェクトは、コンパイル済みの実行ファイル、動的ライブラリ、またはカーネルドライバがシステムのバージョン不一致によって実行またはロードできない問題を解決するための、低レベルな ELF / カーネルモジュール パッチユーティリティです。

本プロジェクトは以下の2つのコア機能をサポートしています：
1. **GLIBC 適応**: 指定された `libc.so.6` からサポートされているシンボルバージョンを自動的に解析し、ターゲットELFファイル（またはディレクトリ）のシンボルバージョン依存関係を互換性を持つようにパッチします。
2. **KMOD 適応**: Linuxカーネルモジュール (`.ko`) の `vermagic` とカーネルシンボルの CRC チェックサムを変更し、カーネルのロードチェックをバイパスして、バージョンが完全に一致しないカーネルへの強制ロードを可能にします。

**使用方法 (Usage):**
```bash
# 【GLIBC 適応モード】
# ./[プログラム名] -c [ホストlibc.so.6のパス] -t [ターゲットELFまたはディレクトリのパス]
./cadapt -c /path/to/your/libc.so.6 -t /path/to/target_elf_or_directory

# 【KMOD (カーネルモジュール) 適応モード】
# ./[プログラム名] -m [ターゲットの .ko ファイル] -s [任意: Module.symvers のパス] -v [任意: ターゲット vermagic 文字列]
./cadapt -m ./my_driver.ko -s ./Module.symvers -v "4.18.0-193.el8.x86_64 SMP mod_unload"
# 注: -s または -v を省略した場合、プログラムは現在実行中のシステムから CRC および vermagic 情報を自動的に抽出しようとします。
```

# ⚠️ 警告：ABI互換性とカーネルパニックのリスクについて
- メタデータの変更のみ: 本ツールはシンボルバージョン・メタデータ（.gnu.version セクションやシンボル CRC チェックサムなど）を 変更するだけ です。バージョンの変更によって引き起こされる ABI (アプリケーション・バイナリ・インターフェース) の非互換性については、一切チェックも修正も行いません（行うこともできません）。

- GLIBC クラッシュのリスク: 関数（例: memcpy や fopen）の動作、引数、または内部データ構造が新旧の libc バージョン間で異なる場合、実行時に ABI の不一致によりクラッシュ（セグメンテーション違反など）したり、不正なデータを生成したりする可能性が非常に高いです。

- KMOD クラッシュのリスク (Kernel Panic): CRC と vermagic の強制変更は、カーネルの安全チェック機構をバイパスします。カーネルのエクスポートシンボル（コア構造体のレイアウトなど）が変更されている場合、変更したモジュールを強制的にロードすると、直接 カーネルパニック (Kernel Panic / Oops) を引き起こします。

- 本ツールは、使用者が新旧環境間の ABI が完全に互換であることを独自に確認済みであることを前提としています。ご自身が何をしているかを正確に理解している場合にのみ使用し、操作前に必ず元のファイルをバックアップしてください。
